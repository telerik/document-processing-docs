Telerik Document Processing documentation — issue #875
Audit date: 2026-10-27
Source revision: a398df43ad46a8198c9bd92dad5e28fe49c7939b

# Executive Summary

Assessment: The documentation has established authoring conventions, but their
accessibility application is inconsistent. The most serious verified barriers are
color-only reference data, screenshot-only navigation instructions, and resource
tables with empty headers. Repeated filename-like image alternatives and skipped
heading levels are the clearest recurring authoring defects.

Estimated content-quality maturity: established practices with uneven enforcement,
not a measured maturity-model certification. Many articles have useful headings,
descriptive links, introductory prose, and labeled examples. Existing guidance
already covers descriptive image alternatives, table headers, and heading order;
the gaps concern both implementation and validation.

This report contains 18 consolidated findings: 3 High, 9 Medium, and 6 Low.
No Critical finding was established. Finding counts denote distinct finding IDs,
not the number of affected cells, screenshots, or repeated occurrences.

Scope is exclusively Markdown documentation, authoring guidance, and referenced
documentation assets. No product functionality, generated-document accessibility,
viewer/designer behavior, runtime keyboard support, or product accessibility claim
was evaluated. Even the article about creating accessible PDFs is assessed only
for its documentation markup.

## F01 — High — Color/Formatting Independence and Tables

File:
/home/runner/work/document-processing-docs/document-processing-docs/libraries/radwordsprocessing/concepts/document-themes.md:123-168

Evidence: line 123 promises "corresponding color values". The 13-column table
starts at line 125. Lines 127-168 contain 42 rows with 12 empty styled spans each,
for 504 color-data cells. Example at line 127:
<span style="display:inline-block;width:12px;height:12px;background-color:#FFFFFF;border:1px solid #ccc;margin-left:4px;"></span>

Impact: screen-reader/text-only readers cannot obtain the documented values.
Disabling CSS or printing without backgrounds removes the data. A lead-in and
valid header row already exist; missing introductory context is not the defect.

Remediation: print each hex value as text; keep the swatch only as a visual
supplement marked aria-hidden="true". Split the wide reference by theme/category.
Example cell: `#FFFFFF` followed by an optional decorative swatch.
This concerns reference content, not accessibility of the themes in the product.

# Repository-Wide Patterns

- Heading skips recur across all four document-processing library areas and
  installation guides, frequently because H4 is used to style an example caption.
  Appendix A supports an outline-aware bulk remediation pass.
- Image coverage differs by syntax: all 506 active Markdown alternatives are
  nonempty, yet seven HTML images omit alt. A Markdown-only image rule misses
  this entire confirmed missing-alt group.
- Nonempty alternatives are not sufficient: two workflows repeat filename-like
  labels for every screenshot. UI labels alone can also omit depicted actions.
  F04 requires text instructions, not simply a longer image label.
- Resource-card grids and screenshot comparisons use table semantics for layout.
  Genuine reference tables also contain implied/repeated or color-only values.
- Labeled code is comparatively consistent (444 of 445 fenced openings have
  labels), but long implementations and external snippets need different checks.
  Do not misclassify closing fences, snippet placeholders, or <img> strings inside
  examples as accessibility failures of the documentation page.
- Context can repair comprehension but not isolated navigation: "here", repeated
  "Actions", raw URLs, and plain-text section labels lose useful distinctions in
  links/heading lists.
- Source warnings are generally textual, but optional-tip labels can conceal
  prerequisites. Guidance should standardize meaning as well as appearance.
- Color words in code, API names, or a diagram explanation are not by themselves
  color-only instructions. F01 is different: the actual reference values have no
  readable text equivalent.
